# 精选市场（Expert market）

DeepSeek Harness 的插件市场页面：把「插件」页里一行一条的索引列表，重做成
一个整页的、可逛的插件目录——分类大卡选方向，卡片看细节，点开就是一页说明书。

## 在哪里

左侧边栏的全局面板区有一个 **精选市场** 入口（在「插件」下方）。点它会在中栏打开
整个页面；切到别的面板再回来，页面状态还在。

## 读什么

不打包、不复制任何数据。页面读的是「插件」页用的同一批市场索引，通过应用自带的
`pluginMarket` Remote（`listIndexes` / `search` / `readEntryDetail`）取数，安装走
`pluginManager`（`installBundle` / `cancelInstall` / `waitForInstall`）。
在「插件」页增删索引，这里会跟着变：`plugin-market/changed` 和
`plugin-manager/changed` 会自动重读。

## 两个视图

页面顶部有两个标签：**逛插件**（市场目录）和**已安装**（本机插件管理）。

### 已安装

一行一个插件，显示名称、包名、版本、状态徽章，并提供操作：

| 操作 | 说明 |
|---|---|
| 点一行 | 打开该插件自己的页面（读本地安装目录的 README，离线可用） |
| 启用 / 停用 | 走 `pluginManager.setBundleEnabled`，切换后自动重读列表 |
| 卸载 | 二次确认后走 `pluginManager.removeBundle` |
| 检查更新 | 走 `pluginManager.listVersions`，进页面查一次，也可手动再查 |
| 单个更新 | 行内「更新到 x.y.z」，走 `pluginManager.updateBundle` |
| 全部更新 | 串行逐个更新，单个失败不中断，最后给汇总 |

### 三种状态分开标注

来源、运行状态、更新状态是三件不同的事，用三种视觉通道表达，互不混淆：

| 维度 | 视觉通道 | 取值 |
|---|---|---|
| 来源 | 徽章 | `DSH 自带`（蓝） / `第三方`（灰） |
| 运行状态 | 左侧竖条 + 状态徽章 | `已启用`（绿） / `已停用`（灰） / `DSH 自带` |
| 更新状态 | 行尾暖色徽章 | `可更新 x.y.z` |

**为什么只有第三方能更新**：宿主对随 DSH 提供的包和 Git 安装的包都不列版本，这是能力边界，不是取舍。

只列出真正存在的插件：Host 返回的目录条目里，未安装的会被过滤掉。已启用的行沿用
分类大卡的那套外框光晕（绿色），停用的行只保留普通描边——状态一眼可辨。

## 页面结构（从上到下）

1. **标题区**：名称、一句话说明、插件源切换（可增删源）、搜索、刷新。
2. **分类大卡**：一排 6 张（窄屏自动降为 3/2/1 列）。每张卡有
   - 分类专属图标徽章（31 个分类各有独立图形，互不重复）
   - 分类名、最多 3 条快捷入口
   - 卡片底部：分类色圆点 + 插件总数
   
   分类多于 6 个时按日期轮换，同一天刷新看到的是同一组，隔天自然变化。
3. **最新热门**：16 个插件名，4 列 4 行，纯名字不带卡片。排序依据是索引真实发布的
   热度字段，取不到就不显示，不编数字。
4. **逛插件**：数量 + 排序（综合 / 星数 / 近期增长 / 最新）。
5. **筛选**：热度、发布时间默认展开；星数、安装状态收在「更多筛选」里，折叠时若有
   条件生效会显示数量。
6. **分类胶囊 + 插件卡片网格 + 分页**（上一页 / 页码 / 下一页）。

插件卡片：分类图标 + 中文名 + 版本与日期 + 两行简介 + 最多 3 个关键词 + 底部分类
标签与版本号 + 「安装」按钮。

插件详情页：返回按钮、图标、中文名、作者与来源、安装/问 AI 按钮、简介、标签、
三格数据条（版本 / 星数 / 作者）、Markdown 说明文档、来源事实表。

## 中文取名（核心特性）

索引里大量插件没有中文标题。本插件为每个插件生成中文名，规则是：

1. 页面先按内置规则（标题词表 + 简介提炼）立刻给出名字，**页面不等模型**；
2. Host 端随后调用模型，读完整简介综合判断功能定位，给出更好的名字；
3. **名字一旦确定就永久不变**——按插件包名绑定、存到本机
   `$DSH_HOME/expert-market/plugin-names.json`，重新跑算法、重建索引、插件升级都
   不会改名；
4. 只有明显坏掉的名字（断在词中间、整句、重复词）会在读取时作废并重新生成；
5. 每条记录记着名字是谁定的（`rule` 规则 / `model` 模型）：规则名还能被模型改进
   一次，模型名此后永久固定。

## 边界

- 不改动、不替换「插件」页，也不读写别的插件的 DOM、样式或组件。
- 不读写 profile 的 `package.json` / patch 层；本插件的 Host 半边只做取名，不挂业务服务。
- 不显示索引没有发布的数字：星数、下载量只有在索引 `metadata.sortKeys` 里有时才出现。
- 界面颜色全部走主题变量（`--dsw-alias-*`），深浅色自动适配；只有分类插画用自有配色。

## 构建

`client.js` 是发布产物，由 `src/` 拼装：

```bash
./build.sh
```

它会依次拼 `src/head.js`、`src/part1..4.js`、`src/tail.js`，做语法检查，然后跑三组测试：

- `test/render-smoke.mjs`：在 VM 里渲染真实索引切片，覆盖搜索、翻页、换源、筛选、
  详情、安装、取名去重、已安装列表的读改删、功能清单与 CSS 规则唯一性
- `test/naming.mjs`：对两个真实索引共 7827 条插件跑取名规则，验证全中文、长度、
  稳定性
- `test/host-naming.mjs`：Host 取名接口端到端，覆盖持久化、改名冻结、坏名自愈、模型纠错

**改代码请改 `src/`，不要手改 `client.js`。**
